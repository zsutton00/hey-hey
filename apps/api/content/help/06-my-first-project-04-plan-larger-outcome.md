A single feature conversation works well when the outcome is focused. Sometimes the discussion reveals that the change crosses several capabilities, requires an up-front design, or needs to be delivered in a deliberate sequence.

When that happens, Hey Hey can suggest creating a plan. If you agree, the agent will help develop the product intent into:

- An up-front design document that records the important decisions.
- Reviewable stages arranged in dependency order.
- Concrete tasks connected to the features they implement.
- A durable execution structure that can be reviewed before work begins.

You might already have a PRD, product brief, or design document to use as source material, but you do not need to arrive with a finished artifact. The planning conversation can create and refine the design with you.

A plan is more than a long task list. It keeps the design, sequencing, dependencies, and implementation work together so that each task can be understood as part of a larger delivery.

Once the plan is ready, you can run its tasks manually or use Automate to coordinate their execution. Manual execution gives you direct control over each launch. Automate is useful when the work is sufficiently defined and you want the system to advance through eligible tasks while preserving checkpoints and opportunities for review.

For isolated development, you can configure the plan to use a worktree. The plan's worktree and branch choice is inherited by its step sessions, keeping the related work together without mixing it into your main checkout. Individual task sessions can also use worktrees, but the plan lets you make the choice once for the coordinated delivery.

**Try it:** Describe a meaningful product change from the relevant feature. If the conversation uncovers several dependent areas or unresolved design decisions, ask Hey Hey to shape it into a plan.

**You're done when:** The work has the right shape: focused tasks for a contained change, or a reviewed design and staged plan for a coordinated delivery.
